# New Project Intake

当仓库还是新项目、样本代码不足时，先用下面 3 轮对话收集信息，再决定默认 squad 并写回 `project-profile.md`。

## 对话 1: 项目目标

- 这个项目最终要交付什么:
  - 网站
  - Web App
  - API
  - 自动化流程
  - 演示稿 / PPT / 单页
  - 内容或营销资产
- 这次最重要的成功标准是什么:
  - 能上线
  - 更好看
  - 更稳定
  - 更快完成
  - 更易扩展

## 对话 2: 技术和交付形态

- 你预计会用什么技术栈:
  - HTML/CSS/JS
  - React / Next.js
  - Python
  - Node.js
  - 还没定
- 主要交付物是什么:
  - 代码仓库
  - 页面
  - 接口
  - 演示文稿
  - 文档

## 对话 3: 当前最先做什么

- 现在第一优先是:
  - 先梳理方案
  - 先搭框架
  - 先做页面
  - 先做后端
  - 先写文案
  - 先验证现有结果

## 典型 squad 映射

- 网站 / 单页 / 演示稿:
  - `Visual Storyteller` + `UI Designer` + `Frontend Developer` + `Reality Checker`
- Web App / 前端产品:
  - `Frontend Developer` + `UI Designer` + `UX Architect` + `Reality Checker`
- API / 后端 / 服务:
  - `Backend Architect` + `API Tester` + `Software Architect`
- 新产品从 0 到 1:
  - `Product Manager` + `Rapid Prototyper` + `Project Shepherd`
- 内容 / 品牌 / 营销:
  - `Content Creator` + `Brand Guardian` + `Visual Storyteller`

## 落盘要求

对话完成后：

1. 选出 1 个主 specialist 和最多 3 个 supporting specialists
2. 写入 `.codex/project-profile.md`
3. 后续任务变化时更新 squad，而不是重建整份 profile
