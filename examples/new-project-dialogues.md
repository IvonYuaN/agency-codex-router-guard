# New Project Intake

When a repository is still a new project and there is not enough code to scan, use the following 3 dialogue rounds before choosing the default squad and writing `project-profile.md`.

## Dialogue 1: Project goal

- What is the final deliverable:
  - website
  - web app
  - API
  - automation workflow
  - presentation / deck / single-page artifact
  - content or marketing asset
- What is the top success metric right now:
  - ready to ship
  - looks better
  - more reliable
  - faster to complete
  - easier to extend

## Dialogue 2: Tech and artifact shape

- What stack do you expect to use:
  - HTML/CSS/JS
  - React / Next.js
  - Python
  - Node.js
  - not decided yet
- What is the main output:
  - code repository
  - page or app
  - API
  - slide deck
  - document

## Dialogue 3: Immediate first move

- What should happen first:
  - clarify the plan
  - scaffold the foundation
  - build the UI
  - build the backend
  - write the copy
  - validate current output

## Typical squad mappings

- website / single-page / presentation:
  - `Visual Storyteller` + `UI Designer` + `Frontend Developer` + `Reality Checker`
- web app / frontend product:
  - `Frontend Developer` + `UI Designer` + `UX Architect` + `Reality Checker`
- API / backend / service:
  - `Backend Architect` + `API Tester` + `Software Architect`
- zero-to-one product:
  - `Product Manager` + `Rapid Prototyper` + `Project Shepherd`
- content / brand / marketing:
  - `Content Creator` + `Brand Guardian` + `Visual Storyteller`

## Persistence rule

After the dialogues:

1. choose 1 primary specialist and up to 3 supporting specialists
2. write them into `.codex/project-profile.md`
3. update the squad when the task changes instead of recreating the whole profile
