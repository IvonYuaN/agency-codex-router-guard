# Karpathy-Style Operating Principles

Distilled from the spirit of `andrej-karpathy-skills`, adapted for `agency-codex-router-guard`.

## Core rules

- Think before editing
- Keep the plan simple
- Prefer the smallest effective change
- Ground decisions in code and evidence
- Verify outcomes instead of narrating intent
- Avoid ornamental complexity

## Router implications

- Do not choose a large squad unless the project truly spans multiple disciplines
- Prefer a primary implementer plus one safety lens
- For scan-based routing, use real repository signals before guessing
- When uncertain, start with onboarding or architecture rather than pretending confidence

## Good application examples

- Unknown codebase:
  - Start with `Codebase Onboarding Engineer`
- Static site with visual requirements:
  - Start with `Visual Storyteller`
  - Switch to `Frontend Developer` when implementation begins
- Existing service with unclear boundaries:
  - Start with `Software Architect` or `Backend Architect`
  - Add `API Tester` when behavior needs verification
